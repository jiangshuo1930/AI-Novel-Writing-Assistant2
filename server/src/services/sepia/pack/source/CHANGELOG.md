## 0.5.1 — 修 bug + 引号规范反转为弯引号

**修掉的 bug**
1. 破折号双倍计数：`count("——")+count("—")` 会把一处算两次（前者是后者子串）。
   改用 `sum(1 for _ in re.finditer(r"—+", body))` 数连续串。
2. 短文本短路导致破折号去重失效：`check()` 在 <100 字时提前 return，
   没产出 L1-1项，`merge_deslop()` 的 em-dash 去重逻辑失效。现在短路分支也先报破折号。
3. deslop JS 不做 strip_meta：markdown 表格/标题被当正文扫，
   表格行还因缺句末标点被判 `truncated` **假阳性**。
   现在 merge_deslop() 先剥非正文结构再交给 JS（临时文件，用后删）。
4. SOFT_WORDS 隐式依赖：从 `load_banned_words()` 内的 `global` 赋值
   提升为模块级常量，消除调用顺序依赖。

**口径统一（sepia↔ deslop）**
- 台词豁免：`“”` 内的套词（深吸一口气/闪过一丝/那一刻明白）**不计**。
  L1-2 与 L1-9 都只扫剥掉台词的叙述层，与 story-deslop 引号遮罩同口径。
  修前两边对同一段台词判定相反，且 sepia 更严会逼作者改正常角色口语。

  直角与半角都是硬伤。对话占比统计同步改为弯引号。
- 第一章稿件、台账、测试脚本的引号已同步转换。
- JS 侧 `QUOTE_PAIRS` 本就同时含 `「」`与 `“”`，**未改动**（保持 md5 与 oh-story 源一致）。

## 0.3.0 — 2026-10-19

- 尝试把对话引号由直角引号「」改为全角弯引号“”。
- **已回滚。** 原因：朱雀对 AI 默认输出的半角 `"` 敏感，直角引号「」是过检的
  结构性差异点之一，改为弯引号后与 AI 输出形态趋同，失去区分度。
- 教训入档：全角引号与半角引号在终端里视觉几乎一致，**必须做编码级检查**
  （U+300C/U+300D vs U+201C/U+201D vs U+0022），不能靠眼睛看。
